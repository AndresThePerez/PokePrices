# PokéPrices ASVS 5.0 Level 1 evidence (P4)

Requirement ids to be filled from the official ASVS 5.0 release.

This is a slim evidence document for the OWASP Application Security Verification Standard 5.0, Level 1, scoped to what
the PokéPrices P4 phase built: authentication, session management, authorization of user-owned data, and the related
input-validation, data-protection and error-handling items. Everything else in the standard is listed at the end as
`not assessed in P4`. It is evidence, not a certification: no automated ASVS harness exists (the gate bundle is
parked), and the verdict on each row is the author's reading of the tests named in it.

How to read it:

- No requirement id appears below. No local copy of the standard was available, and the research notes mark the ids
  they quote as unverified, so each row states the requirement in words under its chapter. The chapter numbers and
  names are the ASVS 5.0 outline as the author recalls it and are not verified against a copy either; they are filled
  in with the ids.
- `pass`: the behaviour is built and a test named in `Evidence` proves it. `na`: the requirement does not apply to this
  product. `gap`: it is not met yet; the row says what is missing and where it goes.
- A test is named by its file path and its exact description, as written in the source file (an escaped apostrophe
  therefore shows as `\'`). Pest tests sit under `api/tests`, Vitest tests under `web/src`.
- The decisions behind these rows are in `docs/adr/0003-accounts-and-sessions.md`; how the endpoints behave is in
  `docs/ACCOUNTS.md`.

## Not assessed in P4

These ASVS 5.0 areas were not assessed, because P4 built nothing they cover or they belong to a later phase:

- A content policy for scripts and styles (the CSP sets no `script-src` or `style-src` yet; the security headers
  are in the V3 row above), cross-origin resource sharing (there is one origin and no CORS configuration).
- File handling (no uploads), WebRTC, OAuth and OpenID Connect (Socialite is a later phase), self-contained tokens
  (none are issued).
- Cryptography beyond the framework defaults (bcrypt hashing, the framework's encryption of the two-factor secret) and
  key management.
- Configuration and deployment hardening of the host, containers and nginx; dependency and supply-chain checks; the
  Deploy prompt owns these.
- Data protection of backups and retention outside the application database.
- Business-logic areas other than the watchlist and portfolio limits.
